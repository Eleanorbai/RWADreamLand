## 1. **📌 角色与权限设计方案（PRD标准格式）**

## **一、角色列表定义**

### 角色建议（结合你PRD和现有代码）：

| **角色标识（英文）** | **中文名** | **简述**                                 |
| -------------------- | ---------- | ---------------------------------------- |
| USER                 | 普通用户   | 平台基础角色，具备基础浏览与内容创建权限 |
| GROUP_MEMBER         | 小组成员   | 加入特定小组的用户，拥有小组内互动权限   |
| GROUP_LEADER         | 小组组长   | 管理所负责小组的成员与笔记分类等事务     |
| REVIEWER             | 内容审核员 | 审核“申请发布”笔记内容，负责内容质量把控 |
| COMMUNITY_MANAGER    | 社区管理员 | 管理小组结构、标签、举报处理、公告发布等 |
| ADMIN                | 超级管理员 | 拥有系统层级的全部权限                   |

## **三、审核流程逻辑说明**

> ✅ 特别说明：为保护用户笔记隐私，**非主动申请发布的内容，审核员不可见**

- 普通用户提交笔记 → 选择“申请发布至学习专区”
- 提交后，笔记进入 REVIEWER 的审核队列
- 审核通过 → 程序员手动对接展示模块 → 展示于学习专区
- 审核不通过 → 原笔记保留在用户个人空间，审核备注展示

## **四、角色继承逻辑（供权限模块编程参考）**

| ----------------- | ------------------ |
| GROUP_MEMBER      | USER               |
| GROUP_LEADER      | GROUP_MEMBER       |
| REVIEWER          | USER               |
| COMMUNITY_MANAGER | REVIEWER           |
| ADMIN             | 全部               |

如果你使用的是 RBAC 模型（Role-Based Access Control），这一设计可直接作为配置蓝本。
